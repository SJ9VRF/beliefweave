# OpenAPI Contract

The FastAPI surface is versioned as a machine-readable snapshot in `results/openapi.json`, generated by `scripts/generate_openapi.py`.

Release-gated routes:
- `GET /health`
- `POST /api/ingest`
- `POST /api/recall`
- `POST /api/governed-recall`
- `GET /api/state/{user_id}`
- `GET /api/memories/{user_id}`
- `GET /api/export/{user_id}`
- `DELETE /api/memory/{memory_id}`
- `PATCH /api/memory/{memory_id}`

`POST /api/ingest` accepts an optional `Idempotency-Key` header (or the equivalent request-body field). Repeating the same user/key/payload is write-free; reusing a key with a different payload returns `409`; replaying an ingest that was explicitly hard-forgotten returns `410` and does not recreate the deleted event.

`tests/test_integrity_and_contracts.py` and API end-to-end tests assert the routes and semantics remain present. The snapshot is a compatibility artifact for this research implementation, not a production SLA.


## Demo access guard

`/api/*` is intentionally **not** an unauthenticated public service. With no `BELIEFWEAVE_DEMO_TOKEN`, the reference app accepts API requests only from loopback clients. If a token is configured, requests must send either `Authorization: Bearer <token>` or `X-API-Key: <token>`. Docker Compose requires the token explicitly. The generated OpenAPI snapshot includes both security schemes. This is a coarse demo transport guard, not production identity or per-user authorization.
