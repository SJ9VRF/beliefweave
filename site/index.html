The idea

I built BeliefWeave around a distinction that kept showing up in long-term memory systems: finding a relevant memory is not the same as trusting it. The system retrieves first, then decides whether the memory is strong enough to use, uncertain enough to ask about, or weak enough to ignore.

Problem

Retrieval can be correct and personalization can still be wrong.

A personal assistant may retrieve a semantically relevant memory that is stale, weakly inferred, context-specific, contradicted, or not actually about the user. Treating relevance as permission creates over-personalization.

The problem

Long-term agents need durable user state across sessions, but the stored past is not automatically the current truth.

Why it is hard

Preferences drift; evidence varies in reliability; the same statement can be temporary, quoted, hypothetical, or context-bound.

Why common approaches fail

Flat RAG and append-only memory optimize recall/relevance but do not independently decide whether a memory should causally influence behavior.

Core idea

Separate relevance from behavioral authority.

BeliefWeave keeps retrieval and decision governance as two different stages. A retrieved belief receives an authority score and is routed to USE, ASK, or ABSTAIN.

Novelty wedge

The contribution is not “another vector memory,” and it is not a claim that personalization restraint itself is new. OP-Bench/Self-ReCheck and PersonaMem-v3 already cover over-personalization and restraint. BeliefWeave therefore narrows the contribution to an explicit per-memory authority decision after retrieval: USE, ASK, or ABSTAIN under explicit costs, with counterfactual intervention and specification tests.

Measured objectives

  • Counterfactual Personalization Regret (CPR)
  • Memory Intervention Fidelity (MIF)
  • False personalization rate
  • Use precision / ASK / ABSTAIN behavior

Architecture

A traceable belief-revision system with explicit loops.

Evidence, memory, current user state, retrieval, and behavioral authority remain inspectable instead of collapsing into a single hidden context.

Interaction→Event + provenance→Observation extraction→Write policy→Typed temporal memory
Current user state←Conflict / drift resolver←Structural safety gates
Query→Retrieval→Decision-aware belief gate→USE / ASK / ABSTAIN→Behavior

Agent loop

Observe → retrieve → score authority → USE / ASK / ABSTAIN → respond → verify outcome → ingest new evidence.

RL / post-training loop

Failure trajectories → authority labels / preference pairs → update learned router/conflict/write components or thresholds → regression eval → redeploy. I designed this interface for post-training work, but I have not run an RL training experiment in this project.

Recovery loop

User correction or contradictory evidence → suspend unsafe belief influence → resolve/supersede state → recompute current user model → retry the next decision with revised authority.

What I built

I designed the memory model, the authority gate, and the evaluation around them.

Research

  • I separated memory relevance from behavioral authority.
  • I introduced USE / ASK / ABSTAIN as the decision layer after retrieval.
  • I defined CPR and intervention fidelity to measure when memory changes behavior for the wrong reason.
  • I built BeliefShiftBench to pressure-test that distinction.

System

  • I implemented typed temporal memory with provenance, expiry, conflicts, and supersession.
  • I built hybrid retrieval and the authority gate.
  • I added memory inspection, correction, soft deletion, and atomic provenance-aware hard forgetting.
  • I kept the full path runnable locally so failures are easy to reproduce.

Engineering choices

  • Multi-valued state is additive unless there is real evidence of replacement.
  • Learned conflict decisions sit behind structural safety checks.
  • The database fails closed on schema versions the code does not understand.
  • The production runtime defaults to hardened V3 while V1/V2 remain selectable for frozen paper reproduction.
  • The public benchmark path does not depend on an external model API.
Experiments

I tested the system in four places where memory tends to go wrong.

Datasets / tasks

  • BeliefShiftBench-v2: 640 controlled cases, split into 320 development + 320 frozen held-out test cases.
  • MemWorldBench executable slice: 20 users × 100 turns.
  • Full synthetic longitudinal dataset: 1,000 users × 100 turns.
  • 360 hard temporal / attribution / multilingual scenarios.
  • OOD paraphrase and retrieval challenge sets.

Baselines

  • Append-only memory.
  • Latest-predicate state.
  • Lexical retrieval.
  • Retrieval-only personalization.
  • Confidence-only and provenance-only authority.
  • Temporal + context filtering.
  • Metadata scoring without hard vetoes.
  • Cost-sensitive authority and oracle references.

Ablations

I removed confidence, provenance, temporal/context checks, structural safety, and conflict handling one at a time to see which failures each guard prevents.

Setup

The prototype runs locally in Python with SQLite and small learned router/conflict components. The benchmark path is deterministic and does not require a hosted model.

Evaluation boundary

These experiments tell me whether the mechanism behaves as intended. They do not yet tell me how much real users benefit from it; that needs a longitudinal user study.

Failure analysis

The most useful design decisions came from things that broke.

A few examples from implementation and evaluation:

Time semantics
Failure
Historical temporary memories expired immediately.
Why
Wall-clock time leaked into simulated state materialization.
Recovery
Made state, retrieval, and validity checks explicitly time-aware.
Attribution
Failure
“My friend says I love sushi” became the user’s preference.
Why
Attribution was collapsed into surface semantics.
Recovery
Added provenance-sensitive third-party guards and regression tests.
Bad metric
Failure
A terminal accuracy metric made append-only look as good as world-state memory.
Why
The final turn explicitly restated the preference.
Recovery
Added reversal-time probes that measure retirement before the new preference is restated.
Bad fixture
Failure
An ablation case labeled “stale” was temporally still valid.
Why
The fixture's expiry was later than its synthetic NOW.
Recovery
Aligned ground-truth temporal labels with synthetic time and reran the full suite.

Model size

Observation router ~212 KB; conflict model ~67 KB; write policy ~6 KB. The memory layer is intentionally lightweight; it is meant to sit beside a larger assistant, not replace one.

Task horizon

The executable longitudinal benchmark reaches 100 turns per user. I also generated a 1,000×100 synthetic dataset for larger offline analysis.

Tool count

The memory core requires no external tool integration. The demo/API exposes 11 HTTP routes around ingest, state, recall, governance, export, and deletion.

Cost / latency

The local benchmark path has no external API spend. Local p95: 48.5 ms ingest, 80.2 ms recall.

Robustness

360/360 hard scenarios; 0 stale retrieval leaks in controlled retrieval eval; OOD router remains a known weakness at 65.8%.

Safety & limitations

Where I would not trust this system yet.

Known failures

Semantic paraphrases, nested quotations, sarcasm, category-level conflicts, and human-calibrated confidence remain incomplete.

Irreversible actions

BeliefWeave itself does not execute irreversible external actions. Any downstream action layer should require separate confirmation and policy checks.

Permission boundaries

Users can inspect, export, correct, soft-delete, or hard-forget memory and source evidence. Weak or conflicted beliefs can ASK or ABSTAIN.

Human escalation

Unresolved conflicts and medium-authority beliefs are explicitly routed to clarification rather than silent personalization.

Privacy boundary

This has not had a formal privacy or security review, so I would not treat it as a production memory service.

Scientific boundary

The current results are synthetic and mechanism-focused. A second sealed specification audit dropped the frozen V2 gate to 53.3%, exposing coverage gaps; challenge-informed V3 hardening fixes that suite but is regression evidence, not independent generalization. No external or human score is claimed.
