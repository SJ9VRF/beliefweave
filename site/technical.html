Technical deep dive

Inside BeliefWeave.

The pieces I added to make memory updates traceable and to keep uncertain memories from silently changing behavior.

Core components

Typed temporal memory

Content, type, source events, source type, confidence, validity, status, scope, supersession, conflict links, and user verification.

Structural safety gates

Learned conflict decisions are bounded by compatible memory types and entity-aware semantics before destructive state updates are allowed.

Decision-aware authority

Retrieved beliefs are separately scored for permission to influence behavior, enabling USE / ASK / ABSTAIN.

Training / learned components

ComponentArtifact sizeRole
Observation router~212 KBRoutes candidate user information into memory-relevant classes.
Conflict classifier~67 KBAssists compatible update/conflict decisions behind structural gates.
Write policy~6 KBBaseline learned policy for persist / temporary / ask / ignore decisions.

I kept these components small so the full path can be run locally. They are not meant to stand in for a frontier model.

Evaluation methodology

Temporal

Preference reversal, expiry, contradiction and state-retirement probes.

Retrieval

Hit@1, Hit@3, MRR, context sensitivity, and stale-memory leak checks.

Authority

CPR, false personalization, use precision, intervention fidelity, ASK/ABSTAIN behavior.

Reliability

Calibration, OOD paraphrases, randomized invariants, an exhaustive 9,600-state authority-policy audit, database integrity, privacy erasure, concurrency stress, and the API contract.
